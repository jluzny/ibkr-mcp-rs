# DEPLOY — IBKR MCP Fixes (stale cache + get_positions PnL + 321 option chain)

## Binary

Staged at: `/data/dev/trading/ibkr-mcp-rs/dist/ibkr-mcp-rs`

## Changes

1. **Stale cache fix** (`src/ibkr/account.rs`): Cache timestamp now refreshes on every Summary event (not just End). Wait loop only returns fresh data (age < cache_ttl=300s). Stale data served with warning if age < stale_max. Refused if age > stale_max.
2. **get_positions PnL enrichment** (`src/ibkr/account.rs`): Calls `pnl_single()` per position to populate market_price, market_value, unrealized_pnl, daily_pnl. Options get /100 multiplier on mark_price. Sentinel filter caps garbage values at +/-1e11. Added `contract_id` field to Position struct and JSON response.
3. **321 option chain fix** (`src/ibkr/market_data.rs`): Resolves real underlying conID via `contract_details()` before calling `option_chain()`. Uses `exchange=""` instead of `"SMART"`. Fixes 321 on INIO/XYZ.

## Deploy Commands

```bash
# 1. Copy the staged binary to the deployment path
sudo cp /data/dev/trading/ibkr-mcp-rs/dist/ibkr-mcp-rs /usr/local/bin/ibkr-mcp-rs

# 2. Restart the MCP service (preserves gateway login)
sudo systemctl restart ibkr-mcp

# 3. Verify
journalctl -u ibkr-mcp.service --no-pager -n 20 | grep -E 'connected|error|fail'
```

## Verification

After deploy, call `get_account_info` 3x rapidly:
- First call: "Fetching fresh account info" or "Fresh snapshot received after wait"
- Second/third: "Serving cached account info (age=Xs)"
- Cache age should stay under 300s on repeated calls

Call `get_positions`:
- Open positions should have non-zero market_price/market_value/unrealized_pnl
- No sentinel values (>1e11) or NaN/Inf in any field
- Options: mark_price = (market_value / |quantity|) / 100

Call `get_option_chain` for AAPL, SPY, INIO, XYZ:
- AAPL/SPY: should return expirations and strikes
- INIO/XYZ: should NOT return error 321 (may return empty if no options listed)
