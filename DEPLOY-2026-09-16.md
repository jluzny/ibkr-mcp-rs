## Anomalies investigated during post-deploy verification (both benign)

1. **NATCOMB returned 0 rows in one sweep — test bug, not a tool bug.**
   `scripts/verify-market-data-tools.py` passed `tag_filters={"underConID":
   "910669144"}`, which is a *leg* conid (first leg of a leg-string), not the
   underlying. A leg conid silently yields 0 rows. Fixed in the script to the
   underlying conid `817815740` (with a comment); after the fix the same call
   returns 5 rows, 3/3 repeats, with the market **closed**. The multi-leg scan is
   not market-hours-sensitive — it only needs the underlying's conid.
2. **The first scanner / option-quote calls after a restart can come back empty.**
   Service log right after 23:03:54:
   `[2108] Market data farm connection is inactive but should be available upon
   demand.usopt` → `[2119] Market data farm is connecting:usopt` → `[2104] ...
   OK:usopt`; during that window the COMBO scan returned `[165] ... no items
   retrieved`. The first `get_option_quote` after the restart returned
   `bid/ask -1, greeks null`; ~90 s later the same call returned the full greeks
   above. Re-run a data call once if a restart just happened.
   Related: after the close, `bid`/`ask` come back `-1` and `get_option_quote`
   returns the model greeks + `close` only — pre-existing behaviour, not new.

## Why sudo is needed

`/usr/local/bin/ibkr-mcp-rs` is `root:root 755` and the unit is a system unit.
`sudo -l` shows `(ALL) ALL` for jiri but with a password requirement and no
NOPASSWD entry for `cp`/`systemctl`; no polkit rule; no `SUDO_PASSWORD`
configured for this profile. `sudo -n true` → "a password is required".

## Known IBKR-side quirks (not bugs in this code)

- `MOST_ACTIVE` at **50 rows returns 0 rows** (5 and 25 rows work; IBKR sends no
  batch at all within 15 s). `HOT_BY_OPT_VOLUME` at 50 rows works fine. The tool
  now reports this explicitly via `notices` instead of returning a bare empty list.
- WSH event data is unentitled on this account (`[10276] News feed is not
  allowed`) — surfaces as `status: "not_entitled"`, exactly as the 2026-09-16
  ib_insync probe suggested (0 rows for every filter variant).
- Option price history remains unavailable from IBKR; `what_to_show` history for
  `OPTION_IMPLIED_VOLATILITY`/`HISTORICAL_VOLATILITY` works on stocks/ETFs/indices
  only. The tools say so rather than pretending otherwise.

## Rollback

The manual install (`scripts/deploy-and-verify.sh` uses `install` with no
backup) left **no** `/usr/local/bin/ibkr-mcp-rs.bak-*`. The pre-change binary is
preserved in the package tarball and hashes to the old deployed value:

```bash
cd /home/jiri/dev/trading/ibkr-mcp-rs
zstd -dc packaging/ibkr-mcp-rs-0.1.0.r28.de15166-1-x86_64.pkg.tar.zst \
  | tar -xO usr/local/bin/ibkr-mcp-rs > /tmp/ibkr-mcp-rs.prev
sha256sum /tmp/ibkr-mcp-rs.prev    # dec576df564a11857ff561c8be1494e8a9c1f90bd48188627f5408efdd9805c9
sudo install -m 0755 -o root -g root /tmp/ibkr-mcp-rs.prev /usr/local/bin/ibkr-mcp-rs
sudo systemctl restart ibkr-mcp
```

`scripts/deploy-native.sh` (added in this task) does take a timestamped
`.bak-<ts>` copy before installing, so future deploys are reversible in place.
Two deploy scripts now coexist: `deploy-native.sh` (general: hash print, backup,
health wait, verify) and `deploy-and-verify.sh` (one-shot, hardcoded hashes for
this deploy). Recommend keeping the former and retiring the latter.
